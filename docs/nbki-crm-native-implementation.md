# НБКИ: автономная исходящая выгрузка из CRM

Решение для КПК «Эксперт Финанс». Рабочий источник новых файлов — только CRM.
Исторические XML/MXL и данные 1С допустимы **однократно** для заполнения
отсутствующих начальных реквизитов и контрольной сверки. Генератор, расчёты,
очередь событий и повторная отправка к 1С не обращаются.

Техническая база: формат Банка России 5.1 с 01.07.2026, предоставленные
примеры НБКИ «ГУТДФ 7.0» и регламент обмена. При противоречии примера и XSD
реализация ориентируется на опубликованную XSD и разъяснение регулятора;
спорное представление проверяется в тестовом обмене. Источники:
https://cbr.ru/ckki/poryadok-formirovaniya-kreditnoy-istorii/ и
https://www.cbr.ru/Content/Document/File/185542/20251209_44_19-8423.PDF.

## Контракт данных

| Группа | Рабочий источник CRM | Вычисление/действие |
| --- | --- | --- |
| Источник | `organizations` + настройки НБКИ организации | ИНН, ОГРН, название из CRM; sourceID, код источника и регистрационные реквизиты сохраняются в настройках один раз |
| Субъект | `members` | ФИО, дата рождения, ИНН, паспорт, адрес; пропуски исправляются в карточке участника, не в XML |
| Сделка | `loans`, `nbki_deals`/`nbki_event_deals`, карточка условий НБКИ | Только один подтверждённый УИД; сумма, срок и ставка CRM; нормативные коды вида/цели/участия сохраняются в CRM и версионируются |
| Событие | операции CRM + журнал событий НБКИ | Время MSK фиксируется в момент операции; дата изменения графика/обеспечения — из утверждения; сроки и просрочка — из графика и календаря |
| Платёж | `loan_payments`, `loan_payment_allocations` | Суммы последнего и всех платежей; части ОД/проценты/пеня; idempotency по первичному ID операции |
| ОД на момент события | первоначальная сумма и журнал платежей | Остаток = сумма выдачи − погашенный ОД; срочный/просроченный ОД — по действовавшему на дату графику и распределениям |
| Проценты | договорные условия, график, расчётный журнал процентов | Начислять тем же алгоритмом, что CRM использует при разнесении; хранить ежедневные проводки и версию ставки/графика. Не приравнивать будущие проценты графика к долгу |
| Пеня | ежедневный журнал начислений, оплаты `penalty_part` | Отдельный остаток и договорная дата предъявления — последний платёж графика |
| ПСК | `loan_psk_calculations` + исходные потоки CRM | Расчёт по 353-ФЗ; версия исходных условий и сумма/процент сохраняются в карточке |
| Среднемесячный платёж | действующий график и остаток долга | Отдельный регуляторный расчёт, не поле `monthly_payment` |
| Обеспечение | `loan_collateral` | Залог/поручительство и отдельные УИД гарантий; изменения — самостоятельное событие 2.4 |

## Порядок разработки и критерии готовности

1. **Единая модель учёта НБКИ в CRM.** Ввести настройки источника,
   версионированные параметры займа (код вида/цели, база дней, даты и ставка),
   неизменяемый журнал событий и начальные остатки. В момент проведения
   платежа записывать событие, снимок графика/распределения и время MSK в одной
   транзакции. Для старых займов восстановить то, что однозначно следует из
   CRM; неустранимые исторические остатки внести разово с датой, основанием и
   сверкой. При изменении графика/ставки/каникул сохранять версию условий.
2. **Расчётный движок на дату события.** Из журнала получить ОД, начисленные
   проценты и пеню, просроченные/срочные части, даты возникновения просрочки,
   ближайший платеж, ПСК и среднемесячный платёж. Каждое число имеет ссылку на
   запись CRM и версию формулы. Контрольные равенства: части платежа и долга,
   остаток ОД, динамика графика, исключение закрытых и договоров без УИД.
3. **Сериализатор ГУТДФ и пакет.** Сначала FL_Event_2_3 (платёж, начисление,
   просрочка), затем 2.1 (условия), 2.4 (обеспечение) и остальные текущие
   события по факту появления соответствующих операций. Схемная версия
   закреплена за файлом. Организация/субъект/сделка/событие формируются из
   нормализованных фактов; XML и SHA-256 неизменяемы. Пакетирование по
   организации, уникальная нумерация, повторная выгрузка того же события не
   создаёт второй документ. Валидировать XSD 5.1 и содержательные инварианты.
4. **Интерфейс и обмен.** В карточке — источник каждого показателя и точечное
   редактирование недостающих мастер-данных. В разделе НБКИ — очередь событий,
   предпросмотр, выпуск/скачивание XML, журнал версий и ошибок. Подпись
   CryptoPro, ZIP и шифрование выполняются локально на ПК владельца;
   закрытый ключ/PIN в CRM не попадают. Квитанции загружаются обратно,
   сверяются с SHA/регномером и меняют статус только после проверки.

**Порядок запуска:** сначала новые события с полным снимком и один выбранный
действующий договор, затем параллельная сверка выходного XML с фактическим
учётом CRM, после тестового обмена — все договоры с УИД. Закрытые договоры
не включать. При отсутствии УИД файл по договору не формировать.

## Что нельзя достоверно вывести из текущих полей

На 29.10.2026 в production 77 активных/просроченных/каникулярных займов
«Эксперт Финанс», 39 с однозначно сопоставленным УИД в реестре событий.
По этим 39 расчёт ПСК записан в CRM. У одного из 39 отсутствуют в карточке
дата выдачи паспорта, кем выдан, код подразделения и адрес регистрации;
это исправляется по первичному документу, не расчётом.

Для исторических операций до появления неизменяемых снимков нет полной
истории изменения ставок/графика и ежедневных начислений процентов. Текущий
остаток и нынешний график не доказывают их размер в прошлом. Для запуска
исторических событий нужна **разовая** точка учёта на выбранную дату:
остаток ОД, начисленные неоплаченные проценты (с разделением на срочные и
просроченные), начисленная неоплаченная пеня, даты начала просрочки и
действовавшие ставка/график. Сначала максимально восстановить их из CRM;
остаточные расхождения запросить у владельца из 1С или первичных документов,
загрузить в CRM с происхождением и больше к 1С не обращаться.

Регистрационные реквизиты источника (sourceID, код, дата создания и номер
регистрации) также фиксируются в CRM один раз. Часть уже встречается в
переданных XML, но при переносе должна быть подтверждена владельцем.
