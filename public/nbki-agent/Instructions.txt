Windows-компонент CRM НБКИ 2.0

Требования: Windows, PowerShell 5.1, КриптоПро CSP 5.0 R3 или новее,
КриптоПро ЭЦП (CAdES COM), дополнительная лицензия КриптоПро TSP Client,
корневые сертификаты УЦ ЦБ. Закрытый ключ остаётся у текущего пользователя
Windows. ПК должен быть включён, пользователь должен войти в Windows.

1. Распакуйте архив. Если установлена версия 1.0, завершите задачу CRM NBKI Exchange
   в планировщике и выполните установку новой версии.
2. В настройках НБКИ CRM создайте ключ подключения ПК.
3. В PowerShell под пользователем — владельцем ключа запустите:
   .\Install-NbkiAgent.ps1 -CrmUrl "https://АДРЕС-CRM/api"
   Введите ключ подключения по запросу установщика. Он хранится с защитой DPAPI.
   Политика выполнения, доверенные корни и настройки безопасности не меняются.
4. В CRM выберите сертификат подписанта; при необходимости отдельный сертификат
   HTTPS-аутентификации. Загрузите действующие открытые сертификаты НБКИ для
   шифрования и проверки квитанций. Укажите адрес TSP вашего аккредитованного УЦ
   из базы знаний НБКИ. Сертификат TSP должен быть согласован с НБКИ.
5. При использовании зарегистрированной в НБКИ МЧД загрузите тот же ZIP-пакет
   МЧД в настройки: он будет вложен в каждый исходящий архив.
6. Сначала выберите подготовку без отправки. После проверки на вашем Windows-ПК
   включите HTTPS API и автоматическое получение квитанций.

Формат: XML + отдельная подпись CAdES-T (DER, с сертификатом TSP), ZIP32,
шифрование ГОСТ 28147-89 сертификатом НБКИ, DER, расширение .zip.p7m / .zip.enc.
Сбой TSP останавливает подготовку: подпись без штампа не отправляется.
Отправка POST multipart/form-data: поле file и pathnm=uploadGUTDF.
HTTP 200 принимается только при ответе Success с точным именем отправленного файла.
При неопределённом результате автоматическая повторная отправка запрещена.

Квитанции: ticket1 — не чаще раза в минуту, проверяются зашифрованный файл
и незашифрованный ZIP отказа. HTTP 404 означает, что квитанция ещё не готова.
ticket2 — только после проверенного положительного ticket1, не чаще раза в 5 минут.
Подпись квитанции проверяется сертификатом НБКИ. После получения квитанции
повторное скачивание прекращается. Локальный кэш квитанций защищён DPAPI.

Проверка TLS обязательна; перенаправления запрещены. Компонент не меняет
настройки безопасности системы. Если политика организации запрещает запуск
скриптов без подписи, обратитесь к своему администратору для штатной установки.
Реальная работа КриптоПро и ГОСТ TLS проверяется на Windows с вашим сертификатом.
